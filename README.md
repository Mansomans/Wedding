# Wedding Weekend Planner

A site for planning a wedding weekend: pick a date, rehearsal dinner, welcome
party, Mass and reception, keep a guest list, and see the whole weekend
simulated on the home page with headcounts and an estimated budget.

The page lives in `public/index.html`. A small Express server in `server.js`
checks the password and stores the shared plan and guest list in Postgres, so
everyone with the password sees the same plan.

## Run it locally

```bash
npm install
npm start
```

Open http://localhost:3000. Without a `DATABASE_URL` the server keeps data in
`data/local.json`. The default password is 09102026; set `SITE_PASSWORD` to
change it.

## Deploy on Render

1. Push this repo to GitHub.
2. In Render choose **New**, then **Blueprint**, and pick the repo. Render reads
   `render.yaml` and creates a web service plus a Postgres database.
3. When prompted, enter `SITE_PASSWORD` (the site password, digits only).
4. After the first deploy, add your custom domain under the service's Settings.

Environment variables the server uses:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (set automatically by the Blueprint) |
| `SITE_PASSWORD` | The password the gate accepts |
| `SESSION_SECRET` | Signs login cookies (generated by the Blueprint) |
| `PORT` | Provided by Render |

## Editing options

Open `public/index.html` and find the block marked `WEDDING WEEKEND — DATA BLOCK`.

- `CONFIG` holds the hint text, sides and guest groups.
- `DECISIONS` holds the five decisions and their options. To add an option,
  push a new object into that decision's `options` array. Only `id` and `name`
  are required; `fixed`, `perGuest`, `capacity`, `time`, `pros` and `cons`
  drive the itinerary and budget. Never reuse an `id`.
- `EXTRAS` holds the other budget lines that can be toggled on the home page.

## API

All routes except login require the session cookie set by a successful login.

| Route | What it does |
|---|---|
| `POST /api/login` | `{password}` sets a 30-day cookie |
| `POST /api/logout` | clears it |
| `GET /api/state` | `{plan, guests, version}` |
| `PUT /api/plan` | replaces the plan (picks, extras, notes) |
| `PUT /api/guests` | upserts one guest or an array of guests |
| `DELETE /api/guests/:id` | removes a guest |
